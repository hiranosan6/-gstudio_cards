## Overview(概要)

ルールの形式は、遊び手がルール盤に並べた札を「1つのルール」としてまとめる形である。
この形があるから、組み立てたルールを保存して後でそのまま開き直せ、ボタン1つで対戦に渡せ、将来は文字列にして人に渡せる。
持つのは札の識別名と調整値だけで、名前や日付は持たない。
壊れたデータや知らない札が混ざっていても、読める部分だけを読んで止まらない。直した点は黙らずに返す(柱3「壊れても遊べる」)。

## Player Fantasy(遊び手の体験)

間接の体験。**「並べた札が、そのまま残る」**

昨日「うちの大富豪」と名前を付けて保存したルールを開くと、入れた札もつまみの数字も元のとおり卓に戻っている。
戻るのは「札の集まり」であり、盤の上の並べ方ではない。札はルール盤が分類ごとに自動で並べ直す(札の並び順は意味を持たないため保存しない。`design/gdd/rule-card-definition.md` 基本の決まり3)。
見えている札の集まりがそのままルールである(柱1「札で考える」)。効かない札(使えない札・未開放の札)が混ざっていれば、そのことを必ず知らせる。
将来の共有でも、同じ札の集まりがそのまま相手に届く。

## Detailed Design(詳細な決まり)

### Core Rules(基本の決まり)

1. **ルールが持つ項目**は次の3つだけとする。

| 項目 | 鍵 | 内容 |
| ---- | ---- | ---- |
| 形式の版 | `format_version` | 整数。1から始める |
| 札の一覧 | `cards` | 知っている札。識別名(`id`)と、名前付きの調整値(`params`)の組 |
| 使えない札 | `unusable_cards` | 知らない識別名の札。解析した値として丸ごと持つ |

   ルールの名前・作成日・元にしたルールは「10 保存と名前付け」、人数・席は「8 対戦の開始と席」が持ち、ルールの形式には含めない。
   これにより、名前が違っても札が同じなら同じルールと判定できる。

2. **調整値の名前は固定**する。識別名と同じく一度決めたら変えず、共通の一覧(`design/registry/entities.yaml`)に登録する。

| 札 | 調整値の名前 |
| ---- | ---- |
| ジョーカー入り(`add_jokers`) | `count` |
| 最初に並べる(`place_on_field`) | `rank` |
| パスで負け(`lose_on_pass_limit`) | `limit` |

3. **文字列の形は JSON** とする(保存・共有で同じ形)。決まった形で書き出した例:

```json
{"cards":[{"id":"act_pass"},{"id":"add_jokers","params":{"count":1}},{"id":"deal_all"}],"format_version":1,"unusable_cards":[]}
```

   札の一覧は識別名を鍵にした対応表ではなく並びにする。JSON の対応表では重複した鍵が解析時に後ろの値で上書きされ、「1枚目を有効」の決まりを守れないため。

4. **読み込むときに一度だけ整える**(正規化)。順番は次のとおり。
   1. 入口の確かめ(「読み込みの手順」の1〜6)。どれかで断ったら、そこで止めて理由を返す。
   2. 版が古ければ、版の移し替えを行う。
   3. `cards` の後ろに `unusable_cards` をつないだ1本の並びを作り、前から順に見る。
   4. 壊れた要素(対応表でない、`id` が無い・文字列でない・空)は捨てる。
   5. 同じ識別名は1つ目だけを残し、2つ目以降は捨てる。1つ目の調整値が壊れていても1つ目を残す(ルール盤では重複を置けないので、手で書き換えたデータでしか起きない)。
   6. 知っている識別名は `cards` へ、知らない識別名は `unusable_cards` へ振り分ける。知らない札は実行部分には渡さない。
   7. `cards` の札の調整値を整える(式1)。欠けていれば既定値、知らない名前の調整値は捨てる、調整値を持たない札に付いた値は捨てる。
   8. 札が0枚でも正しいルールとして扱う(注意はルール盤が出す)。

5. **整えの報告を返す**。読み込みの結果には、整えたルールと一緒に、変えた内容の一覧を付ける。表示は 7 ルール盤が受け持つ(開いた直後に「直した点」として示す)。

| 種類 | 持つ情報 |
| ---- | ---- |
| 値を直した | 識別名、調整値の名前、元の値、直した値(丸めた/既定値にした) |
| 調整値を捨てた | 識別名、調整値の名前 |
| 要素を捨てた | 並びの中の位置(0から数える)、理由(壊れている/重複) |
| 使えない札へ移した | 識別名 |
| 使えない札から戻した | 識別名 |
| 数を書けない値を null にした | 識別名(使えない札の中の無限大・非数) |

   何も変えていなければ一覧は空である。

6. **書き出すときの決まった形**は次のとおり。エンジンの書き出し関数(`JSON.stringify`)は使わず、自前で組み立てる(エンジンの更新で形が変わらないように)。
   - 鍵はすべて文字の番号の順(Unicode の符号位置の順)に並べる。最上位は `cards`・`format_version`・`unusable_cards` の順になる。
   - 空白・改行は入れない。
   - `cards` も `unusable_cards` も、識別名を文字の番号の順に並べる。重複は手順5で取り除いてあるので、同じ識別名は並ばない。
   - `cards` の調整値は、既定値と同じでも省略せずにすべて書く。既定値を後で変えても、保存したルールの意味が変わらないようにするため。調整値を持たない札には `params` を書かない。
   - 数・文字列の書き方は「書き出しの形が崩れないようにする決まり」に従う。

7. **同じルールかどうか**は、決まった形で書き出した文字列の一致で判定する。置いた順番に左右されない。

8. **安全のための決まり**:
   - 受け取った文字列はデータとしてだけ読む。JSON の解析には `JSON` の実体の `parse()` を使い、戻りの誤りの番号で成否を判定する(`JSON.parse_string` は失敗と文字列 `null` を見分けられないため使わない)。
   - 次は使わない: `str_to_var`、`bytes_to_var`、`bytes_to_var_with_objects`、`load`、`ResourceLoader`、`JSON.to_native`、`JSON.from_native`、資源ファイル(`.tres` など)としての読み込み。どれも物を組み立てたり任意の処理を動かしたりできるため。
   - 識別名・調整値の名前は、登録済みの表を引くことだけに使う。ファイルの場所の組み立て、`call`・`get`・`set`・`has_method` などに渡さない。
   - 上限(式2): 文字列4000文字、入れ子の深さ16、札64枚、識別名40文字。超えたら読み込まない(どの上限かを含めた理由を返す)。
   - Godot の JSON は数をすべて小数で返す。整数として使う前に、有限であること・整数の値であること・範囲内であることを小数のまま確かめる(大きすぎる小数を整数に直すと結果が決まらないため)。

9. **知らない札は残したまま保存する**(使えない札)。要素は `id` と `params` 以外の項目も含めて丸ごと持つ。新しい版で開き直せば `cards` に戻る。

10. **未開放の札**(仕組み12で開放していない札)が読み込んだルールに入っていたら、`cards` に残す。
    - ルール盤には置いたまま「未開放」と表示する(7 ルール盤)。札箱から新たに置くことはできない(`design/gdd/rule-card-definition.md` の状態表)。
    - 対戦では無視する(実行部分に渡さない)。
    - 対戦を始めるときに、効かない札(使えない札＋未開放の札)の枚数を「N枚は効きません」と必ず知らせる(8 対戦の開始と席)。

### 読み込みの手順(入口の確かめ)

上から順に確かめ、最初に当てはまった理由だけを返す。

| 順 | 確かめること | 断る理由 |
| ---- | ---- | ---- |
| 1 | 先頭の文字コードの目印(U+FEFF)が1つあれば取り除く。そのうえで文字数が上限以下か | 長すぎる(文字数) |
| 2 | 入れ子の深さ(文字列の外の `[` と `{` の重なり)が上限以下か。解析の前に文字列を1回なめて数える | 長すぎる(入れ子の深さ) |
| 3 | JSON として解析できるか(空の文字列・途中で切れた文字列を含む) | 形が壊れている |
| 4 | 最上位が対応表か | 形が違う |
| 5 | 版が読めるか(「特殊な場合」の版の判定) | 版が読めない/新しい版で作られたルールです |
| 6 | `cards`・`unusable_cards` が、あるなら並びか。無ければ0枚とする | 札の一覧の形が違う |
| 7 | 札の数と識別名の長さが上限以下か(式2) | 長すぎる(札の数/識別名) |

### States and Transitions(状態と移り変わり)

ルールの形式そのものは状態を持たない「値」とする。

| 場面 | 持ち主 | 変更 |
| ---- | ---- | ---- |
| ルール盤の上 | 7 ルール盤 | できる(いつも整った形を保つ。重複は置く時点で置けない) |
| 対戦中 | 8 → 4 | できない(対戦を始めるときに写しを渡して固定する) |
| 保存したもの | 10・11 | 10 を通して上書きする |

### Interactions with Other Systems(他の仕組みとの関係)

| 相手 | 受け取るもの | 渡すもの |
| ---- | ---- | ---- |
| 2 ルール札の定義 | 識別名、調整値の名前・範囲・既定値 | — |
| 4 ルールの実行部分 | — | 整えた札の一覧(使えない札・未開放の札は除く) |
| 7 ルール盤 | 置く・外す・調整値の変更 | 札の一覧、使えない札の一覧、整えの報告 |
| 8 対戦の開始と席 | — | 固定した写し、効かない札の枚数 |
| 10 保存と名前付け | — | 決まった形の文字列、同じルールかどうかの判定、断った理由 |
| 11 保存データ | 保存してある文字列 | 決まった形の文字列 |
| 9 特殊札・12 札の開放 | 追加された札、開放の状態(形は変わらない) | — |

**版を上げるとき**:
- 札が増えるだけなら版は上げない(知らない札の決まりで吸収する)。
- 形そのものが変わるとき、既存の札に調整値を足すとき、調整値の名前を変えるとき、調整値の範囲を狭めるときは版を上げる。古い識別名・調整値の名前から新しいものへの置き換え表を持つ。
- 廃止した識別名は使い回さない。
- 読める最も古い版(最小対応版)と今の版は定数にし、テストでは差し替えられるようにする。

**技術判断の記録(ADR)に回すこと**: 保存の方法(`user://` にファイルとして書くか、ブラウザの保存機能を直接使うか、保存の確定をどう確かめるか)。4.7 でのブラウザ保存の振る舞いは、実際に書き出して確かめる。

## Formulas(計算式)

### 式1 調整値の整え

`整えた値 = x が有限の数なら 整数化(四捨五入(範囲内に丸める(x, 最小, 最大)))、そうでなければ 既定値`

**変数:**

| 変数 | 型 | 範囲 | 意味 |
| ---- | ---- | ---- | ---- |
| x | 読み込んだ値 | 何でも入りうる | 保存データにある値 |
| 最小・最大・既定値 | 整数 | ルール札の定義のとおり | 例: `count` は 1〜2(既定 1) |
| 整えた値 | 整数 | 最小〜最大 | 実行部分に渡す値 |

- 「有限の数」だけを数として使う。文字列(`"2"` を含む)・真偽の値・null・並び・対応表・非数・無限大は既定値にする。文字列から数への変換はしない。
- 無限大(正・負とも)を最大・最小ではなく既定値にするのは意図どおりである。無限大は壊れた値として扱う。値の大きさと結果の向きは、有限の数の中でだけそろう。
- 範囲内に丸めるのを先に行う(1e300 のような値で桁があふれないように)。最小・最大が整数なので、順番を逆にしても結果は同じ。
- 四捨五入は、ちょうど0.5のとき0から遠い方へ寄せる(Godot の `round` と同じ)。
- 値を直したときは、整えの報告に「値を直した」を足す(基本の決まり5)。

**出力の範囲:** 必ず最小〜最大の整数。
**例(`count` 1〜2):** 1.4→1、1.5→2、2.5→2、9→2、-0.5→1、0→1、1e300→2、無限大→1、負の無限大→1、"2"→1、null→1。
**例(`rank` 1〜13、四捨五入の向き):** 6.5→7、7.5→8、7.4→7、7.6→8。
**例(`limit` 1〜5):** 5.49→5、5.5→5。

### 式2 上限の判定

`受け入れる = 文字数(文字列) ≤ 4000 かつ 入れ子の深さ ≤ 16 かつ 要素の数(cards) + 要素の数(unusable_cards) ≤ 64 かつ 文字列である各 id で 文字数(id) ≤ 40`

**変数:**

| 変数 | 型 | 範囲 | 意味 |
| ---- | ---- | ---- | ---- |
| 文字数 | 整数 | 0以上 | Unicode の符号位置の数(Godot の `String.length()`)。バイト数でも、見かけの1文字でもない |
| 入れ子の深さ | 整数 | 0以上 | 文字列の外にある `[`・`{` の重なりの最大。最上位の対応表が1 |
| 要素の数 | 整数 | 0以上 | 整える前の数。壊れた要素と重複も数える |

- 確かめる順番と返す理由は「読み込みの手順」のとおり。
- 識別名の上限は、捨てられるだけの要素(重複など)にも効く。上限を超える識別名は壊れた入力とみなし、ルール全体を断る(意図どおり)。
- 書き出すときも、書き出した文字列の文字数が4000以下であることを確かめる(超えたら保存を断る)。

**出力:** 受け入れる/受け入れない(どの上限かを含む理由付き)。
**例:** 4000文字・深さ16・64枚・40文字はそれぞれ受け入れ、4001文字・深さ17・65枚・41文字はそれぞれ受け入れない。

### 定義 同じルールかどうか

- `同じ(A, B) = (決まった形(A) == 決まった形(B))`
- 必ず成り立つこと: `決まった形(読み込み(決まった形(x))) == 決まった形(x)`(何度書き出しても同じ)

## Edge Cases(特殊な場合)

### 読み込まず、理由を返すもの(異常終了はしない)

- **もし JSON として解析できない(空の文字列・途中で切れた文字列を含む)なら**: 読み込まない。理由「形が壊れている」。
- **もし入れ子が深すぎる(17以上)なら**: 解析する前に断る。理由「長すぎる(入れ子の深さ)」。解析器そのものの深さの上限には頼らない。
- **もし最上位が対応表でない(並び・数・文字列・null)なら**: 読み込まない。理由「形が違う」。
- **版の判定**(Godot は数を小数で返すので、小数のまま判定する):
  - `format_version` が無い・数でない(文字列・真偽の値・null など)・有限でない・整数の値でない(1.5 など)なら「版が読めない」。1.0 は1として扱う。
  - 最小対応版より小さいなら「版が読めない」。
  - 今の版より大きいなら(2.0 や 1e300 を含む)「新しい版で作られたルールです」。
  - 最小対応版以上で今の版より小さいなら、版を移し替えてから整える。書き出すときは今の版になる。
- **もし上限(式2)を超えるなら**: 読み込まない。理由「長すぎる」に、どの上限か(文字数/入れ子の深さ/札の数/識別名)を付ける。
- **もし cards(または unusable_cards)があるのに並びでないなら**: 読み込まない。理由「札の一覧の形が違う」。無いときは0枚とする。

### その部分だけを外す・整えて、残りを読むもの

- **もし要素が対応表でない、id が無い・文字列でない・空の文字列なら**: その要素だけを捨て、報告に「要素を捨てた(壊れている)」を足す(使えない札にも入れない)。
- **もし id が知らない識別名なら**: 使えない札へ移す。大文字・小文字は区別する(`Deal_All` は `deal_all` と別)。
- **もし最上位に決まった3項目以外の項目があるなら**: 捨てる。
- **もし知っている札の要素に id と params 以外の項目があるなら**: 捨てる。使えない札の要素は捨てずに丸ごと持つ(基本の決まり9)。
- **もし知っている札の params が対応表でない(null・並び・数)なら**: 調整値が無いものとして既定値を入れる。
- **もし知らない名前の調整値なら**: 捨て、報告に「調整値を捨てた」を足す。
- **もし調整値を持たない札に params が付いているなら**: params ごと捨て、書き出しでも書かない。
- **もし使えない札に params が付いているなら**: 整えずに値として丸ごと持つ。
- **もし unusable_cards の中に今の版で知っている識別名があるなら**: cards へ戻して調整値を整え、報告に「使えない札から戻した」を足す(未開放なら「未開放」とする)。
- **もし同じ識別名が cards と unusable_cards の両方にあるなら**: 前にある cards 側だけを残す。
- **もし同じ識別名の札が2枚あるなら**: 1枚目を残す。1枚目の調整値が壊れていて2枚目が正しくても、1枚目を整えた値を使う。報告に「要素を捨てた(重複)」を足す。
- **もし JSON の対応表の中に同じ鍵が2つあるなら**: 解析器が採った方の値を使う(Godot は後ろの値を採ると見られるが未確認)。見分けられないため、仕様として受け入れる。

### 札の数

- **もし札が0枚なら**: 正しいルールとして扱い、`"cards":[]` と書き出す。
- **もし札が全部使えない札なら**: cards は0枚、unusable_cards に全部を残し、実行部分には0枚を渡す。
- **もし未開放の札しかないなら**: cards に全部を残し、実行部分には0枚を渡す。未開放の札も決まった形に含まれる。
- 実行部分に渡す札が0枚のとき、対戦を始められるかは 7 ルール盤と 8 対戦の開始と席が決める。

### 書き出しの形が崩れないようにする決まり

- **数**:
  - 有限で、整数の値で、絶対値が 2^53(9007199254740992)以下なら、小数点を付けずに整数で書く(Godot は 3 を 3.0 と書き出すおそれがあるため)。-0 は 0 と書く。
  - それ以外の有限の数は、有効数字17桁の指数の形で書き、仮数の末尾の0と、残った末尾の小数点を取り除く。指数は `e` の後に必ず符号を付け、先頭に0を付けない。例: 0.1 → `1.0000000000000001e-1`、1e300 → `1e+300`、2.5e20 → `2.5e+20`。小数の精度は落とさない。
  - 無限大・非数(使えない札の中にだけ現れうる)は `null` と書き、報告に「数を書けない値を null にした」を足す。
- **文字列**: 前後を `"` で囲む。`"` と `\` は前に `\` を付け、U+0000〜U+001F は `\u` と小文字の16進4桁で書く。それ以外の文字(日本語を含む)はそのまま書く。`/` は書き換えない。
- **鍵の並び**: どの対応表でも、鍵を文字の番号の順に並べる(使えない札の中の対応表も含む)。空白は入れない。
- **もし書き出した文字列が4000文字を超えるなら**: 保存を断り、理由「長すぎる(文字数)」を返す。既定値を省略しないため、読み込んだ文字列より長くなりうる。読み込めたルールが保存できない場合があるのは、大きな使えない札を含むときだけであり、受け入れる。
- ゲームの版が変わり、知らなかった札が知っている札になると決まった形も変わる。これは意図どおり。同じゲームの版の中では何度書き出しても同じ形になる。

### 古い版のゲームで開いた場合(受け入れる)

- 新しい版で範囲を広げた調整値(例: 将来 `count` が1〜3になる)を古い版で開くと、範囲内に丸められ、保存し直すと元の値は失われる。
- ブラウザ版はいつも最新が届くため、まれな場合として受け入れる。整えの報告で「値を直した」と知らせる。

## Dependencies(依存関係)

- **依存先**: 2 ルール札の定義(`design/gdd/rule-card-definition.md`、承認済み)— 識別名、調整値の名前・範囲・既定値、未開放の札の状態
- **依存元**: 4 ルールの実行部分、7 ルール盤、8 対戦の開始と席、10 ルールの保存と名前付け、11 保存データ(いずれも未設計)
- **関係する側**: 9 特殊札、12 札の開放(札を足すが、形は変えない)
- これらの設計書を書くときは、この設計書への参照を必ず入れる(両方向の参照)。
- **引き継ぐこと**:
  - 7 ルール盤: 札を分類ごとに自動で並べる/「未開放」と「使えない札」の表示/整えの報告を「直した点」として示す/未知の識別名を画面に出すときは、書式を指定する記号(`RichTextLabel` の書式指定など)として解釈させない
  - 8 対戦の開始と席: 対戦を始めるときに「N枚は効きません」と知らせる/この設計書から移した結合テスト(写しの固定)
  - 4 ルールの実行部分: 3ルールを読み込んで対戦が決着するかの結合テスト(`design/gdd/rule-card-definition.md` 合格の基準5と合わせる)
  - 10 保存と名前付け・11 保存データ: 共有の文字列を短くする必要が出たとき、圧縮の層を足すか

## Tuning Knobs(調整できる値)

| 値 | 既定 | 安全な範囲 | 影響 |
| ---- | ---- | ---- | ---- |
| 文字列の上限 | 4000文字 | 2000〜8000 | 小さすぎると大きなルールを保存できない。大きすぎると悪意のある入力に弱い |
| 入れ子の深さの上限 | 16 | 8〜64 | 知っている札だけなら深さ4で足りる。使えない札の中身の深さを許す幅。大きすぎるとブラウザで解析器が深く潜る |
| 札の上限(使える札＋使えない札) | 64枚 | 32〜128 | 札の種類が増えたら見直す |
| 識別名の上限 | 40文字 | 32〜64 | 今の最長は `flow_clear_on_all_pass` の22文字 |
| 形式の版(今の版) | 1 | 上げるだけ | 「版を上げるとき」に当てはまるときだけ上げる |
| 最小対応版 | 1 | 1〜今の版 | これより古い版は「版が読めない」で断る |

**決まり**: ルール札の調整値の範囲は広げるだけにする。狭めるときは形式の版を上げる(保存したルールの意味が黙って変わらないように)。

## Visual/Audio Requirements(見た目と音)

この仕組みには見た目と音の要件はない。

## UI Requirements(画面の要件)

表示は他の仕組みが受け持つ。この仕組みは表示のための情報を返すだけである。
- 使えない札・未開放の札・整えの報告の表示 → 7 ルール盤
- 「N枚は効きません」の知らせ → 8 対戦の開始と席
- 読み込み・保存を断った理由の表示 → 10 保存と名前付け
- 断る理由は決まった6種類で返す: 「形が壊れている」「形が違う」「版が読めない」「新しい版で作られたルールです」「長すぎる」(どの上限かを付ける)「札の一覧の形が違う」

## Acceptance Criteria(合格の基準)

単体テストは `tests/unit/rule_format/` に置く。札の定義・開放の状態・上限・版の定数は外から差し込み、ファイルの読み書きはしない。
期待する文字列は、テスト用の固定データ(`tests/fixtures/rule_format/`)の定数と1文字ずつ比べる。

### 項目と形

1. **GIVEN** 最上位に `name`・`created_at`・`players` の鍵を足した文字列、**WHEN** 読み込んで書き出す、**THEN** 最上位の鍵は `cards`・`format_version`・`unusable_cards` の3つだけ。(決まり1)
2. **GIVEN** 基本の決まり3の例と同じ札を、空白・改行入りで別の順に書いた文字列、**WHEN** 読み込んで書き出す、**THEN** 基本の決まり3の例と1文字も違わない。(決まり3・6)
3. **GIVEN** 差し込んだ16枚の定義、**WHEN** 調整値の名前を集める、**THEN** `add_jokers`=`count`、`place_on_field`=`rank`、`lose_on_pass_limit`=`limit` で、他の13枚は0個。(決まり2)

### 整え(1件ずつ)

4. **GIVEN** `{"id":"foo_bar","params":{"x":1},"note":"a"}` を含む、**WHEN** 整える、**THEN** `unusable_cards` に `id`・`params`・`note` を持つ要素が1件入り、実行部分に渡す一覧には入らず、報告に「使えない札へ移した」が1件ある。(決まり4・9)
5. **GIVEN** `add_jokers` を count 2 → count 1 の順に2枚、**WHEN** 整える、**THEN** 1枚だけ残り count は2で、報告に「要素を捨てた(重複)」が1件ある。(決まり4の5)
6. **GIVEN** cards に count `"2"` の `add_jokers`、unusable_cards に count 2 の `add_jokers`、**WHEN** 整える、**THEN** count は1(1枚目を整えた値)。(特殊な場合の重複)
7. 次の入力をそれぞれ別のテストとして整え、表のとおりになる。(決まり4の7・式1)

| 入力 | 期待 | 報告 |
| ---- | ---- | ---- |
| `add_jokers` に params なし | count 1 | なし |
| `place_on_field` に rank 7.6 | rank 8 | 値を直した(7.6→8) |
| `place_on_field` に rank 6.5 / 7.5 | rank 7 / 8 | 値を直した |
| `lose_on_pass_limit` に limit 9 | limit 5 | 値を直した(9→5) |
| `lose_on_pass_limit` に limit 0 | limit 1 | 値を直した(0→1) |
| `add_jokers` に count 1 と speed 3 | count 1、speed は消える | 調整値を捨てた(speed) |
| `act_pass` に count 1 | params が消える | 調整値を捨てた(count) |
| `add_jokers` に params `[1]` | count 1 | なし |

8. **GIVEN** 整える関数に直接、count として無限大・負の無限大・非数・1e300・`"2"`・null・true を渡す、**WHEN** 整える、**THEN** 1e300 は2、それ以外は既定の1。(式1)
9. 次の壊れた要素を1件ずつ含めて整え、その要素だけが捨てられ、報告に「要素を捨てた(壊れている)」が1件ある: 数 `3`、`{}`(id なし)、`{"id":5}`、`{"id":""}`。(特殊な場合)
10. **GIVEN** `{"id":"Deal_All"}`、**WHEN** 整える、**THEN** 使えない札に入る。(特殊な場合の大文字・小文字)
11. **GIVEN** `"cards":[]` の文字列と、`cards` の無い文字列、**WHEN** 読み込んで書き出す、**THEN** どちらも失敗せず札は0枚で、`"cards":[]` と書かれる。(決まり4の8)
12. **GIVEN** unusable_cards に `{"id":"deal_all"}`、**WHEN** 整える、**THEN** cards に入り、報告に「使えない札から戻した」が1件ある。(特殊な場合)

### 版

13. **GIVEN** 今の版を2、最小対応版を1に差し込み、版1の文字列と置き換え表(`old_x`→`deal_all`)を与える、**WHEN** 読み込む、**THEN** 版2の形になり、`old_x` は `deal_all` に置き換わり、知らない札はそのまま残る。(決まり4の2)

### 書き出し

15. **GIVEN** `deal_all`・`act_pass`・調整値なしの `add_jokers` の順に置いたルール、**WHEN** 書き出す、**THEN** 固定データの文字列 `{"cards":[{"id":"act_pass"},{"id":"add_jokers","params":{"count":1}},{"id":"deal_all"}],"format_version":1,"unusable_cards":[]}` と一致する。(決まり6)
16. **GIVEN** 識別名が `zz_b`・`zz_a` の順の使えない札、**WHEN** 書き出す、**THEN** `zz_a`・`zz_b` の順に並ぶ。(決まり6)

### 同じルールかどうか

### テスト以外の確かめ(合否のテストとは分ける)

- **共通の一覧との一致**: 調整値の名前と範囲が `design/registry/entities.yaml` と一致することを、データの検査(`/consistency-check`)で確かめる。

- **性能の測定**: 札20枚(16種類＋知らない札4枚)のルールの読み込みと整えを100回行い、平均を記録する。目安は1回1ミリ秒以内(試作で最も遅い1手が約4ミリ秒だったため、その4分の1を読み込みに許す)。測定の手順は性能の測定の手順書に置く。
- **試し遊びの観察**: 保存して開き直したとき、札の集まりと調整値が同じに見えるか、「直した点」と「N枚は効きません」の知らせが伝わるか。
