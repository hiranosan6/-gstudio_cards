# ルール札の定義

> **状態**: 承認済み(2026-11-23 簡易確認)
> **作成者**: ユーザー＋Claude
> **最終更新日**: 2026-11-23
> **関わる柱**: 柱1「札で考える」、柱3「壊れても遊べる」

## Overview(概要)

ルール札は、トランプ遊びのルールを「配り方・手番の行動・出せる条件・場の流れ・上がり条件」の5つの分類に分けた部品である。
遊び手はこの札をルール盤に並べて、自分のルールを組み立てる。
この仕組みは、札1枚ごとの名前・説明・分類・記号・調整できる値(札の上の小さなつまみ)・相性(一緒にあるとよい札、両立しない札)を定める。
最小構成は、試作(`prototypes/rule-engine/REPORT.md`)で大富豪・7ならべ・ババ抜きの再現を確かめた16枚とする。
札が実際に何を起こすか(振る舞い)は、ルールの実行部分(仕組み4)が受け持つ。

## Player Fantasy(遊び手の体験)

- **直接の体験**: 札を手に取った瞬間に「これを入れたら何が起きるか」が想像できる。「パス[3]回で負け」のつまみを回して、遊びの手触りが変わるのを楽しめる。
- **間接の体験**: 大富豪は10枚、7ならべは8枚、ババ抜きは6枚の札でできていると気づく。「ルールは部品でできている」という発見が、自分で作る意欲につながる(柱1「札で考える」)。

## Detailed Design(詳細な決まり)

### Core Rules(基本の決まり)

1. 札1枚は次の項目を持つ。

| 項目 | 内容 |
| ---- | ---- |
| 識別名 | 英字の snake_case。一度決めたら変えない(保存したルールが参照するため) |
| 名前 | 8文字以内 |
| 説明 | 20文字以内 |
| 分類 | 配り方/手番の行動/出せる条件/場の流れ/上がり条件 のどれか1つ |
| 記号 | 分類の記号(扇・手・鍵・輪の矢印・旗。`design/art/art-bible.md` 4章) |
| 絵柄 | 図にしたアイコン |
| 調整値 | 0個か1個。名前・既定値・最小・最大・表示の形(例: 「パス[3]回で負け」)を持つ |
| 一緒にあるとよい札 | 識別名の一覧 |
| 両立しない札 | 識別名の一覧 |
| 段階 | 最小構成/特殊札 |
| 最初から使えるか | はい/いいえ(いいえは開放が必要) |

2. 同じ札は、1つのルールに1枚までしか置けない。
3. 札の意味は「置かれているかどうか」と「調整値」だけで決まる。置く順番や位置で意味は変わらない。
4. 相性の悪い組み合わせでも置くことはできる。ルール盤は注意を出すだけで、禁止しない(柱3「壊れても遊べる」)。
5. トランプには強さを持たせない。強さは「出せる条件」の札だけが決める。「2が最強」が無いときは数字の順(Aが最も弱く、Kが最も強い)とする。これは意図した決まりである。
6. 「順位を付ける」または「最後は負け」が1枚でもあれば、1人が残るまで対戦を続ける。どちらも無ければ、最初の1人が上がった時点で対戦を終える。
7. 「出せる手が無いときの自動のパス」など、札が置かれていないときの進め方は、ルールの実行部分(仕組み4)が決める。この設計書は札の意味だけを定める。

#### 最小構成の16枚

| 識別名 | 分類 | 名前 | 説明 | 調整値 |
| ---- | ---- | ---- | ---- | ---- |
| `deal_all` | 配り方 | 全部配る | 山札を全員に配り切る | — |
| `add_jokers` | 配り方 | ジョーカー入り | ジョーカーを山札に入れる | 枚数 1〜2(既定 1) |
| `place_on_field` | 配り方 | 最初に並べる | 配った後、指定の数字を場に並べる | 数字 1〜13(既定 7) |
| `act_play` | 手番の行動 | 出す | 手札から場に出せる | — |
| `act_pass` | 手番の行動 | パス | 何もせずに手番を終えられる | — |
| `act_draw_from_next` | 手番の行動 | 隣から引く | 次の人の手札から1枚引く | — |
| `cond_stronger` | 出せる条件 | 強い札だけ | 場より強い札しか出せない | — |
| `cond_same_count` | 出せる条件 | 同じ枚数 | 同じ数字を場と同じ枚数で出す | — |
| `order_daifugo` | 出せる条件 | 2が最強 | 3が最も弱く、2が最も強い | — |
| `cond_adjacent` | 出せる条件 | 隣の数字 | 同じマークの隣の数字に出す | — |
| `flow_clear_on_all_pass` | 場の流れ | パスで流す | 全員パスで場を流す | — |
| `flow_discard_pairs` | 場の流れ | ペアを捨てる | 同じ数字2枚を自動で捨てる | — |
| `win_empty_hand` | 上がり条件 | 手札0で上がり | 手札が無くなったら上がり | — |
| `win_ranking` | 上がり条件 | 順位を付ける | 1人残るまで続けて順位を付ける | — |
| `lose_on_pass_limit` | 上がり条件 | パスで負け | パスが指定回数を超えたら負け | 回数 1〜5(既定 3) |
| `lose_holding_last` | 上がり条件 | 最後は負け | 最後まで残った人が負け | — |

既存の3ルールの組み合わせ:
- 大富豪(10枚): 全部配る・ジョーカー入り(1)・出す・パス・強い札だけ・同じ枚数・2が最強・パスで流す・手札0で上がり・順位を付ける
- 7ならべ(8枚): 全部配る・最初に並べる(7)・出す・パス・隣の数字・手札0で上がり・順位を付ける・パスで負け(3)
- ババ抜き(6枚): 全部配る・ジョーカー入り(1)・隣から引く・ペアを捨てる・手札0で上がり・最後は負け

#### 相性(試作の結果から)

| 札 | 一緒にあるとよい札 | 両立しない札 |
| ---- | ---- | ---- |
| 強い札だけ | 出す、パスで流す | 隣の数字 |
| 同じ枚数 | 出す | — |
| 2が最強 | 強い札だけ | — |
| 隣の数字 | 出す、最初に並べる | ジョーカー入り、強い札だけ |
| 隣から引く | ペアを捨てる | — |
| パスで流す | 出す | — |
| 順位を付ける | 手札0で上がり | — |
| パスで負け | パス | — |

相性は片方の札にだけ書けばよい(ルール盤が両方向に読む)。

### States and Transitions(状態と移り変わり)

| 状態 | 意味 | 次の状態 |
| ---- | ---- | ---- |
| 未開放 | 札箱に見えるが使えない | 開放されると「使える」へ(仕組み12) |
| 使える | 札箱にあり、ルール盤に置ける | 置くと「配置済み」へ |
| 配置済み | ルール盤にある。調整値を変えられる | 外すと「使える」へ |

未開放の札は札箱から置けない。ただし、読み込んだルール(共有で受け取ったものなど)に入っていた未開放の札は、ルール盤に「未開放」と表示したまま残り、対戦では効かない(`design/gdd/rule-format.md` 基本の決まり10)。

最小構成では、すべての札が最初から「使える」状態である。札の定義そのもの(名前や相性)は遊んでいる間に変わらない。

## Formulas(計算式)

### 強さ(既定)

`強さ = 数字`(ジョーカーは 14)

### 強さ(「2が最強」が置かれているとき)

`強さ = (数字 + 10) mod 13`(ジョーカーは 13)

**変数:**

| 変数 | 型 | 範囲 | 意味 |
| ---- | ---- | ---- | ---- |
| 数字 | 整数 | 1〜13 | A=1、J=11、Q=12、K=13 |
| 強さ | 整数 | 0〜14 | 大きいほど強い |

**出力の範囲:** 既定は 1〜14、「2が最強」は 0〜13。
**例:** 「2が最強」のとき、3→0、K→10、A→11、2→12、ジョーカー→13。よって 3<4<…<K<A<2<ジョーカー。

### パスで負け

`負け = パスの回数 > 回数(調整値)`

**変数:**

| 変数 | 型 | 範囲 | 意味 |
| ---- | ---- | ---- | ---- |
| パスの回数 | 整数 | 0〜 | 自分で選んだパスの回数(出せる手が無いときの自動のパスは数えない) |
| 回数 | 整数 | 1〜5 | 札の調整値 |

**例:** 回数3なら、4回目のパスで負け。

## Edge Cases(特殊な場合)

- **調整値が範囲外のとき**(保存データが壊れているなど): 範囲内に丸める。例: 回数9は5にする。
- **知らない識別名があるとき**(古い・新しい保存データ): その札だけを無視し、ルール盤に「使えない札」として表示する。対戦は止めない。
- **データ上、同じ札が2枚あるとき**: 1枚目だけを有効にする。
- **両立しない札が両方あるとき**: 注意を出すだけ。「隣の数字」があれば場は並べる形になる。
- **「隣の数字」と「ジョーカー入り」が両方あるとき**: ジョーカーは出せない札として手札に残る。
- **「2が最強」だけがあり「強い札だけ」が無いとき**: 置けるが効果はない。相性の注意を出す。
- **手番の行動の札が1枚も無いとき**: 誰も何もできない。全員が自動のパスを続け、「誰も動けず打ち切り」になる(実行部分の役目)。ルール盤は「手番の行動が無い」と注意を出す。
- **上がり条件の札が1枚も無いとき**: 決着しない。手数の上限で「長すぎて引き分け」になる(実行部分の役目)。

## Dependencies(依存関係)

- **依存先**: 1 トランプの定義(`design/gdd/playing-card-definition.md`、承認済み)
- **依存元**: 3 ルールの形式、4 ルールの実行部分、7 ルール盤、9 特殊札、12 札の開放(いずれも未設計)
  - 4 ルールの実行部分へ引き継ぐこと: 自動のパスの定義、7ならべの「パスで負け」になった人の手札の扱い、引き分け2種類(長すぎて引き分け/誰も動けず打ち切り)
- **共通の一覧**: 16枚の識別名・強さの式・調整値の既定は `design/registry/entities.yaml` に登録済み
  - これらの設計書を書くときは、この設計書への参照を必ず入れる(両方向の参照)。

## Tuning Knobs(調整できる値)

| 値 | 既定 | 安全な範囲 | 影響 |
| ---- | ---- | ---- | ---- |
| ジョーカーの枚数 | 1 | 1〜2 | 2枚にすると大富豪では切り札が増え、ババ抜きでは負けが2人になりうる |
| 最初に並べる数字 | 7 | 1〜13 | 端の数字(1・13)では片側にしか伸びない |
| パスで負けの回数 | 3 | 1〜5 | 少ないほど厳しく、決着が早い |
| 名前の文字数の上限 | 8 | 6〜10 | 札の見た目に収まるか |
| 説明の文字数の上限 | 20 | 16〜24 | 一行で読めるか |

## Visual/Audio Requirements(見た目と音)

- 見た目の決まり(`design/art/art-bible.md` 3〜5章)に従う。大きさはトランプの1.25倍。上部に分類の色帯と記号、中央に名前と絵柄、下部に説明。
- 調整値は、札の中に「[3]」のような枠で示す。
- 札を置く・外す音は、音(仕組み17)で決める。

## UI Requirements(画面の要件)

- 札の説明は長押しかタップで出す。マウスを乗せたときだけ出る表示は作らない。
- 調整値は札の上の「−」「＋」で変える。押せる部分は32ピクセル以上(`design/art/art-bible.md` 7章)。
- 相性の注意は橙の地に「!」の記号で示す。操作は止めない。

## Acceptance Criteria(合格の基準)

1. 16枚がデータとして定義され、全項目が埋まっている(自動テスト)
2. どの札も名前が8文字以内、説明が20文字以内(自動テスト)
3. 識別名に重複がない(自動テスト)
4. 相性で参照している識別名がすべて存在する(自動テスト)
5. 3つのルールを定義から組み、実行部分で4人×100局ずつ回すと全局が決着する(結合テスト)
6. 範囲外の調整値は範囲内に丸められる(自動テスト)
7. 知らない識別名を含むルールを読み込んでもエラーで止まらない(自動テスト)
8. 「2が最強」のとき、強さが 3<4<…<K<A<2<ジョーカー の順になる(自動テスト)

## Open Questions(未解決の問い)

- 札の名前が伝わるかは、試し遊びで確かめる。
- 「2が最強」を、「強さの順」を選べる1枚の札(調整値で順を選ぶ)にまとめるか。特殊札(仕組み9)の設計で検討する。
- ジョーカーを同じ数字の組に混ぜて出せるようにするか。特殊札で検討する。
