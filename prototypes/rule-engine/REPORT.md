## 試作の報告: ルールの実行部分

*日付: 2026-11-23 / Godot 4.7.1(画面なし)/ 判定: 進める*

### 仮説
部品化したルール札(5分類・約20枚)の組み合わせを読むだけの実行部分で、
大富豪・7ならべ・ババ抜きを動かせる。どんな組み合わせでも止まらずに終わる。
簡単な判断のコンピューターで1手0.5秒以内に収まる。

### やり方
- GDScript で画面のない対戦の進行部分を作った(約550行。うち実行部分は約390行)。
- ルールは「札の id と調整値の並び」というデータで表した。ルール札は構想書の対応表どおり16枚。
  - 配り方: 全部配る/ジョーカーを入れる(1〜2枚)/特定の札を場に並べる(数字1〜13)
  - 手番の行動: 出す/パス/隣から引く
  - 出せる条件: 強い札を出す/同じ枚数で出す/強さの順(3が最弱・2が最強)/隣の数字
  - 場の流れ: 全員パスで流す/ペアを捨てる
  - 上がり条件: 手札0枚で上がり/順位を付ける/パス回数で負け(1〜5回)/最後に残ると負け
- 必ず終わるための仕組みを2つ入れた。
  - 手数の上限: 300手×人数で「長すぎて引き分け」
  - 動けない状態の打ち切り: 誰の札も動かない手番が人数×4回続いたら「誰も動けず打ち切り」
- 毎手、札の総数が変わらないこと(札が消えたり増えたりしないこと)を検査した。
- コンピューターは、自分の手札と「出せる手の一覧」だけを見る。出せるなら一番弱い札(同じ強さなら枚数の多い組)を出し、出せなければ引き、それも無ければパスする。
- 手抜きした点: 画面・動き・保存・特殊札・エラー処理。ジョーカーは単独でしか出せない。

### 数値
- 最も遅い1手: 約4ミリ秒(目標0.5秒の125分の1以下)
- 1000局の総実行時間: 約5秒(1局あたり約5ミリ秒)
- 作り直しの回数: 0回(最初の実装で3ルールとも動いた)

### 判定: 進める
ルール札の組み合わせだけで3つのルールが動き、16枚で足りた。
どんな組み合わせでも必ず終わり、札の総数のエラーも0件だった。柱3「壊れても遊べる」は、手数の上限と打ち切りで実現できる。
速さにも大きな余裕があり、より賢いコンピューター(先読み型)を載せる余地もある。
一方、でたらめな組み合わせの多くは「終わるが決着しない」。これを遊び手にどう伝え、どう直させるかが、本番の設計の要になる。

### 本番に進めるにあたって
- **ルール盤(仕組み7)**: 組み合わせの相性の悪さを事前に知らせる。止めずに注意だけ出す(柱3)。
  - 「強い札を出す」には「全員パスで流す」が要る
  - 「隣から引く」には「ペアを捨てる」が要る
  - 「隣の数字」には始点(特定の札を場に並べる)が要る
  - 「隣の数字」とジョーカーは両立しない(ジョーカーを入れても意味がない)
  - 上がり条件が無ければ決着しない
- **対戦の結果の伝え方**: 引き分けを「長すぎて引き分け」と「誰も動けず打ち切り」に分け、原因の札の候補を示す(仕組み13 振り返りの土台)。
- **実行部分とコンピューターの境界**: 「出せる手の一覧」だけでつなぐ方式で問題なかった(仕組みの一覧の「手を選ぶ口」)。
- **トランプの定義**: 強さを持たせず、ルール札で決める方式で問題なかった。
- **調整値の候補**: 手数の上限(300手×人数)、打ち切りまでの動かない手番(人数×4)。本番の設計書で調整できる値にする。
- **本番の工数の見込み**: 実行部分は中〜大。試作のコードは流用せず、作り直す。

### 分かったこと(他の仕組みへの影響)
- 大富豪では、場を出した人が上がって居なくなったとき、「全員パスで流す」の条件(誰がパスすれば流れるか)に注意が要る。
- 7ならべの「パス回数で負け」では、負けた人の手札を場に並べる処理が必要(特殊な並べ方になる)。
- ババ抜きの「隣から引く」は、相手の手札を見ずにでたらめに選ぶだけで成り立つ。見えない情報を扱う作りは、対戦の状態(仕組み5)で「見える部分だけを渡す」形にすればよい。
- 見直し頻度が最小限のため、専門役による判定(CD-PLAYTEST)は省略した。判定は試作者としての判断による。
