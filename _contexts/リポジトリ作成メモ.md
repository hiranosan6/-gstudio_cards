## 柱とやらないこと(2026-11-23 確定)
### 柱
1. 札で考える — ルールはすべて札として目に見え、手で並べられる。迷ったら文字の設定項目より札1枚で表せる形。
2. 3秒で試せる — 直してから遊び始めるまでを最短に。迷ったら作り込んだ演出より待たずに遊べること。
3. 壊れても遊べる — 変なルールでも止まらず、コンピューターがそれなりに遊ぶ。迷ったら禁止より遊ばせて結果で気づかせる。
4. トランプの手触り — 卓・札・配る動きなど紙のトランプらしさ。迷ったら新しい表現より見慣れたトランプの見た目。
### やらないこと
- 自由記述のプログラム/スクリプトによるルール作成(柱1を崩す)
- 通信対戦(規模と柱2から外れる)
- 52枚＋ジョーカー以外の独自カード(柱4を崩す)
### 遊びの流れ
- 30秒: 札を1枚入れ替え→対戦→数手で手応え / 5分: 1局3〜5分→気づき→直す
- 1回の遊び: 改造ルールを1つ仕上げ名前を付けて保存 / 長期: 使える札(表現の幅)が増える
- 見直し頻度が最小限のため、この段階の専門役による見直しは省略。

## ルール札の定義の設計書(/design-system 2026-11-23)
- 決定: トランプの定義は仮の約束(マーク4種・数字1〜13・ジョーカー、強さなし)で進める/調整値は札の上で変える(0〜1個)/同じ札は1種類1枚/相性(一緒にあるとよい札・両立しない札)は札の定義に持たせ、ルール盤は注意だけ出す
- 16枚の名前: 全部配る・ジョーカー入り・最初に並べる・出す・パス・隣から引く・強い札だけ・同じ枚数・2が最強・隣の数字・パスで流す・ペアを捨てる・手札0で上がり・順位を付ける・パスで負け・最後は負け
- 強さ: 既定=数字、2が最強=(数字+10) mod 13、ジョーカーは最強
- 記録: design/gdd/rule-card-definition.md(状態: 設計済み・確認待ち)
- 簡易確認で承認(2026-11-23): 「順位を付ける/最後は負けがあれば1人残るまで続ける」「既定の強さはAが最弱」「手番の行動が無いと打ち切り」を追記。自動のパス等は実行部分へ引き継ぎ。16枚・強さの式・既定値を design/registry/entities.yaml に登録。確認の記録ファイルは作らない(ユーザー選択)

## トランプの定義(/design-system 2026-11-23 承認)
- 54種類(52枚＋黒・赤のジョーカー)。ジョーカーは赤黒で区別するが見た目だけ違い働きは同じ(ユーザー選択)。1枚のときは黒
- 並べ順: ♠→♥→♦→♣、数字順、ジョーカーは最後(黒→赤)。式 = マーク番号×13+(数字−1)
- 強さは持たない。トランプは1組のみ。ジョーカーはペア・同じ数字の組に入らない
- ルール札の定義の「仮の約束」を確定に更新。共通の一覧に並べ順と山札の枚数を登録
- 記録: design/gdd/playing-card-definition.md

## ルールの形式(着手)
- 概要は遊び手への効果の角度で書く/体験は間接/共有は文字列にできる形式だけ備え、共有の画面は作らない
- 専門役4役(クリエイティブディレクター・システムデザイナー・ゲームプレイプログラマー・エンジンプログラマー)の意見を集約し、ユーザーが決定(2026-11-23):
  - 体験の言い表し: 「並べた札が、そのまま残る」(並び順は持たない)
  - 調整値は名前付きで固定(count・rank・limit を識別名と同じく不変とし共通の一覧に登録)
  - 知らない札は「使えない札」として残したまま保存
  - 共有の文字列は JSON に決める(専門役の意見は「短い形」と「JSON」で分かれていた)
  - 形式に持たせるのは版番号＋札の集まり＋使えない札のみ。名前・日付は10、人数・席は8に任せる
  - 未開放の札を含むルールは置けるが「未開放」と表示し対戦では無視(推奨どおり)
  - 試作の不具合: 重複札で最後の1枚が残っていた(設計は1枚目を有効)。本番で直す
