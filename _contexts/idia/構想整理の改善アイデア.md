# 次回さらに良い結果を得るためのアイデア(構想整理)

- 新しいリポジトリは、作業を始める前に GitHub 上で空のまま作っておくと、記録をすぐ push できる。
- 「作ってみたいルールの具体例」を2〜3個先に挙げてもらうと、ルール札の種類と粒度を早く見積もれる。
- 試作の前に、大富豪・7ならべ・ババ抜きを「配り方/手番の行動/出せる条件/場の流れ/上がり条件」に分解した表を作ると、札約20枚で足りるかを机上で確かめられる。
- 試作では、でたらめな組み合わせの「決着しなかった原因」を最初から分類して集計すると、ルール盤の注意文の候補が一度で得られる。
- 本番では、Godot をこの環境の設定(セットアップ処理)で入れておくと、毎回の取得が不要になる。
- 小さな土台の仕組み(トランプの定義など)は、決める点だけ先に質問し全章を一度に下書きすると、往復が少なく済んだ。中〜大の仕組み(ルールの形式・実行部分)は章を分けて確認する。
- 作業環境が再起動されることがあるので、承認のたびにコミットとpushをしておくと安全(今回も再起動を挟んだが作業は失われなかった)。
- 専門役のサブエージェントは「詳細な決まり」用(4役)と「計算式・特殊な場合・合格の基準」用(2役)の2回に分けて並行させると、役どうしの食い違い(上限超過の扱いなど)を次の回で解消できた。最初から食い違いを探す役を1つ入れると、さらに往復が減る。
